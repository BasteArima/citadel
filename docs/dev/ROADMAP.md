## Этап 1. Каркас

Цель: сервер на Go отдаёт Go-курс из формата v1, и в браузере он выглядит так же, как `legacy/go-course/`.

**1.1. Go-модуль и команды проверки**
- [x] `go.mod`, папки `cmd/citadel`, `internal/…`, `web/`, `content/`.
- [x] `Taskfile.yml`: `fmt`, `vet`, `test`, `check` (проверка курсов), `run`, `up` (Docker).

**1.2. Формат v1**
- [x] Типы курса, узла и блока в `internal/course`; блок с полем `type`.
- [x] Реестр типов блоков: известные типы и их обязательные поля.
- [x] Обновить `CONTENT-FORMAT.md`: как v1 выглядит на самом деле.

**1.3. Конвертер v0 → v1**
- [x] `citadel convert-v0`: исполняет JS-файлы курса и строит v1. Незнакомое поле блока — ошибка, а не молчаливая потеря.
- [x] Части по маркерам `{ part }`, вопросы «Проверь себя» — в свою часть, «Сделай руками» и «Проверка» — частями практики.
- [x] Тест: каждый урок v0 после конвертации сохраняет все блоки и вопросы.
- [x] `content/go/course.json` — результат конвертации, лежит в репозитории.

**1.4. Проверка курса**
- [x] `citadel check`: схема, уникальные id, известные типы блоков.
- [x] Ссылки `{{термин}}` — на словарь, `{{>урок}}` — на существующий узел, `deps` — на существующие узлы.
- [x] Вопросы: у выбора верный индекс в границах, у порядка не меньше двух пунктов; у «предскажи» есть вывод или ошибка.

**1.5. Сервер**
- [x] `citadel serve`: `/healthz`, `GET /api/courses`, `GET /api/courses/{id}`.
- [x] Фронтенд встроен в бинарник (`embed`), курс открывается по `/c/{id}/`.

**1.6. Движок читает курс с сервера**
- [x] Шаг 1: прежний движок без изменений логики, перед ним — переходник из v1 в его внутреннюю модель. Курс выглядит как раньше.
- [x] Шаг 2: движок читает v1 сам, типы блоков — модули с общим интерфейсом (отрисовка, текст для озвучки, правило выполнения). Переходник удалён. Прогресс — по id вопросов, тексты Go-курса — в данных ([0006](decisions/0006-engine-modules-and-question-ids.md)).

**1.7. Docker Desktop**
- [x] `Dockerfile` (многоэтапная сборка), `compose.yaml`: порт 8080, healthcheck, restart.
- [x] Сервис поднимается на Docker Desktop на ПК владельца и открывается на `http://localhost:8080`.

## Этап 2. Вход и синхронизация, деплой

Сначала всё живёт на Docker Desktop на ПК владельца (`localhost:8080`), на домашний сервер — когда этап 2 готов.

- [x] Вход по имени и коду доступа. Код — из переменной окружения ([0007](decisions/0007-sign-in-and-progress-sync.md)).
- [x] SQLite в Docker-томе: курсы с версиями, пользователи, сессии, прогресс. Изменившийся курс из `content/` при запуске становится новой версией.
- [x] Прогресс на сервере, слияние по свежести отметок; без сети отметки копятся и уходят при подключении.
- [ ] Открыть сайт совсем без сети (service worker).
- [x] Импорт прогресса из прежнего курса: кнопка «Скачать прогресс для Citadel» в `legacy/`, файл — на главной курса: вопрос `test[N-1]` урока — это `урок.qN`, `hands.check[N-1]` — `урок.hN`.
- [x] Бэкап базы через SQLite (`VACUUM INTO`): `task backup`. Восстановление проверено.
- [x] Гайд `docs/guides/self-hosting.md`: поднять, навести домен в Nginx Proxy Manager, обновить, сделать бэкап.
- [ ] Владелец поднимает на сервере, ассистент проверяет сайт чтением.

## Этап 3. Каталог и страница курса

Сводка по курсам для ученика — `GET /api/overview?today=…`: пройдено, решено, сколько повторить сегодня, следующий урок. Дату присылает браузер, чтобы «сегодня» совпадало с днём ученика.

- [x] Каталог плитками на `/`: статус, процент, «Продолжить», фильтр по статусу. «Продолжить с того же места» — последнее открытое место на этом устройстве.
- [x] Общее «Повторить сегодня» по всем курсам: сводка в каталоге, сами вопросы — на странице курса (`#review`).
- [x] Страница курса: паспорт, прогресс, разделы с уроками и статусами, «Опирается на», «Что дальше» (поле `requires` в паспорте), «Как засчитывается».
- [x] Профиль на `/profile`: цепь из звеньев-курсов, сводка, скачать и загрузить прогресс файлом, тема, выход.
- [ ] Отдельная страница «Повторения» с одной очередью карточек из всех курсов (макет есть) — когда курсов станет больше одного.
- [x] Урок по макету «Урок · часть»: общая шапка сайта, колонка текста до 820 px, правая колонка («Опирается на», «Термины части», «Скажи на собесе»), части таблетками, низ части одной строкой. Озвучка, режим чтения, тема и подсказки клавиатуры остались.

## Этап 6. Агенты

Сценарий: владелец запускает Claude Code у себя на ПК, и агент создаёт или правит курс на задеплоенном сервисе. Всё, что делает агент, попадает черновиком в очередь, публикует админ ([0003](decisions/0003-agents-edit-via-drafts.md)).

- [ ] Токены агентов с правами: «читать», «предлагать правки», «создавать курсы». В базе — только хеш, токен показывается один раз.
- [ ] API правок: черновик, проверка, отправка на публикацию. Новый курс от агента — тоже черновик.
- [ ] MCP-сервер поверх API (`/mcp`, транспорт HTTP): прочитать курс и схему блоков, предложить правку, создать курс, узнать статус правки.
- [ ] Подключение одной командой: после создания токена админка показывает готовую строку `claude mcp add --scope user --transport http citadel <адрес>/mcp --header "Authorization: Bearer <токен>"`. Агенту вводить токен не нужно.
- [ ] Очередь правок в админке: разница, принять, отклонить с комментарием.
- [ ] `proposal_status`: агент видит, приняли ли правку, и комментарий админа.
- [ ] Паспорт курса для агента: правила курса отдаются через API.
