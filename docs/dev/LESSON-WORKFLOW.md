# Как делается урок

Порядок работы над уроком, стратегия производства курса, проверка и грабли. Перенесено из правил Go-курса 29.10.2026 и относится к любому курсу платформы; специфичное для Go помечено.

Каким урок должен получиться для ученика — `docs/guides/authoring.md`. Формат данных — `CONTENT-FORMAT.md`.

## 1. Как делается урок

Специфичное для Go-курса (версия Go, база Go Mafia, задания в `study/practice/`) для других курсов заменяется их аналогами из паспорта курса.

### Порядок работы над одним уроком

1. **Чек-лист покрытия из базы.** Прочитать заметки темы в базе Go Mafia (`K:\Obsidian\Go-Mafia\backend\theory\`), её карточки, вопросы из `backend\questions\theory\` и упоминания в `backend\questions\by-companies\`. Правило базы — «всё, что нужно для ответа на собесе, должно быть здесь», значит, урок обязан покрыть всё это.
2. **Источник правды — не база, а исходники Go, спецификация и запуск на Go 1.27.** До 29.10 уроки проверялись на 1.26 — при правке урока его выводы перепроверяются на 1.27, а упоминания версии в тексте обновляются. База местами отстаёт от свежих версий.
3. **Текст урока** — по формату ниже.
4. **Анимация** для каждой ключевой механики. Лучше всего заходит сцена «что было бы, если…», где видно, как ломается наивный подход.
5. **Задание руками** — папка в `study/practice/` со стартовым состоянием. Решение ассистент проверяет у себя во временной папке, в практику не кладёт.
6. **Проверка** — раздел 7.
7. **Независимая сверка.** Отдельный агент сравнивает готовый урок с базой, карточками и вопросами с собесов (в базе Go Mafia: `questions/theory`, `questions/by-companies`, задачи в `questions/tasks`) и ищет пробелы и расхождения. Агент только читает и ничего не правит. Каждое расхождение проверяется запуском или по исходникам Go: база тоже ошибается. На пилоте сверка нашла 30 пробелов и 10 расхождений, три из них — противоречия внутри самого урока.
8. **Запись** в журнал `study/ПЛАН.md` и отметка в `docs/dev/ROADMAP.md`, если пункт оттуда.

### Формат урока

По образцу курса знакомого «Сети с нуля»:

1. Метаданные (номер, раздел, время) и лид.
2. **Простыми словами** — три шага: реальная ситуация из Go-бэкенда, где без этой вещи плохо (сервис уведомлений, платёжный провайдер, профиль под нагрузкой, баг в проде); простое объяснение на этой ситуации; фраза «Как сказать на собесе» — готовая формулировка для запоминания. Не бытовые и не игровые аналогии: что объяснили в «простыми словами», то пользователь и воспроизведёт на собесе. Розетка, пуля из Unity, бейдж и коробки эту проверку не прошли.
3. **Проблема, которую решает** механизм — сначала боль, потом инструмент.
4. Объяснение: короткие абзацы, таблицы, код, схемы, анимации. Блоки «Если ты из C#», «Осторожно», «На собесе».
5. **Сделай руками** — шаги с командами, ожидаемым выводом, разделом «Если не получается» и вопросами «Проверь, что понял» по тому, что пользователь увидел у себя.
6. **Главное из урока.**
7. **Проверка** — 8–9 вопросов: выбор, ввод слова, сортировка карточек. Объяснение после каждого ответа.
8. Через 1, 3 и 7 дней после прохождения вопросы урока возвращаются на главную.

**Урок делится на части.** Одна длинная страница отталкивает: «гора текста», и начинать не хочется. Теорию режут на 2–4 части по 3–4 минуты чтения, каждая — отдельная страница. «Сделай руками» и «Проверка» (вместе с «Главным из урока») — отдельные части практики. В меню под текущим уроком видны его части с отметками, внизу каждой части — кнопка «Дальше». Резать по смысловым границам, а не по счётчику слов. Урок 10 — первый урок в таком формате. Остальные переводятся после отзыва пользователя.

**Отметка «пройдено» должна быть заработана.** Открытие части ничего не засчитывает — пользователь прямо спросил, почему «заход в тему равен её прохождению». Каждая часть теории заканчивается блоком «Проверь себя» на 2 вопроса из теста урока (поле `part: N` у вопроса). Часть засчитывается, когда на них ответили верно. В финальной «Проверке» эти вопросы не повторяются, но входят в общий счёт, и урок засчитывается только при всех решённых вопросах. Часть без своих вопросов засчитывается, когда дочитана до конца, но не при открытии.

Каркас — как у знакомого: меню слева, колонка текста справа. Палитра — «Графит» (с 29.10): нейтральный тёмно-серый фон и приглушённый синий акцент, светлая тема — почти белый фон. Цвета только через токены в `style.css`; контраст текста ≥ 4.5 в обеих темах. Подписи блоков — обычным шрифтом, без капса и разрядки. Макеты — в Claude Design (блок «Редизайн · Графит»), история редизайна — `study/РЕДИЗАЙН.md`, дальнейшие этапы — `docs/dev/ROADMAP.md`.

Формат данных — `docs/dev/CONTENT-FORMAT.md` (v0 — прежний движок в `legacy/go-course/`, v1 — цель этапа 1).

## 2. Стратегия производства курса

- **Пачками по 3–5 уроков одного блока за заход**, с полной проверкой. Ограничивает не объём контекста, а проверка.
- **На одну-две пачки впереди пользователя, не дальше.** Если формат поменяется, переделывать придётся только написанное.
- **Порядок — по провалам диагностики:** интерфейсы (готово) → слайсы (уроки 3–5, в них войдут задачи s1–s4) → строки и мапы (6–7) → каналы, select, sync (17–19) → GC и память → дальше по плану.
- **Пишет один автор, линейно внутри блока.** Уроки ссылаются друг на друга и делят словарь и тон, параллельные авторы это ломают.
- **Агенты — для проверки**, а не для написания. Параллельное написание независимых разделов (например, system design и Postgres) — только по явной просьбе пользователя: это многоагентный прогон, он заметно дороже.
- В длинной сессии ранний контекст сжимается. Перед новым уроком перечитывать соседние уроки с диска.

## 3. Проверка перед тем, как отдать

- `gofmt -l` и `go vet` на всех файлах `study/practice/`.
- **Каждый вывод программы, текст ошибки компилятора и паники в уроке получен запуском** на Go 1.27, а не взят из памяти. Это правило уже окупилось: в пилоте проверка нашла пять собственных ошибок ассистента.
- `node --check` на всех JS-файлах курса.
- Браузер через конфигурацию `legacy` из `.claude/launch.json`: все шаги каждой анимации, светлая и тёмная тема, ширина телефона без горизонтального скролла, консоль без ошибок. После проверки стереть тестовый прогресс (`localStorage.removeItem('gocourse-v1')`).

## 4. Грабли, на которые уже наступили

- **Лигатуры шрифта.** JetBrains Mono рисует `!=` как `≠` и `->` как стрелку — в учебном коде это вводит в заблуждение. В CSS курса лигатуры в коде отключены. Не включать обратно.
- **Ложные замеры аллокаций.** Если значение известно компилятору заранее, он кладёт его в статические данные, и упаковка выглядит бесплатной. Значения для замеров — только из функций с `//go:noinline`.
- **Go 1.25–1.26 изменили классические ответы.** Маленький слайс, растущий через `append`, стартует в буфере на стеке, и cap растёт как `1 2 3 4 8…` вместо `1 2 4 8…`. `make([]T, n)` с размером из переменной больше не уходит в кучу автоматически. Задачи на рост cap строить так, чтобы оптимизация не срабатывала.
- **Пересечение CSS-классов.** Однажды класс `.now` у баннера совпал с классом текущего деления, и деление раздулось в кирпич. Новым классам давать уникальные имена.
- **Превью локальных файлов** в браузере ассистента показывает статичный снимок без скриптов. Проверять только через локальный сервер `legacy`.
- **Размерные классы аллокатора.** cap у `[]byte` после `append` бывает больше удвоенного, потому что память выдаётся блоками фиксированных размеров. Это не выравнивание.
- **Python на Windows пишет CRLF.** `open(..., "w")` без `newline="\n"` переводит весь файл на переводы строк Windows, и `gofmt` начинает ругаться на Go-файлы. Писать с `newline="\n"`.
- **Обратный слеш в командах.** Двойной `\\` в тексте скрипта, переданного через оболочку, схлопывается в одиночный. Скрипты правки, где важны `\n` внутри JS-строк, сначала сохранять в файл и потом запускать.
- **Нумерация уроков сквозная.** Вставка урока сдвигает номера всех следующих. Перед вставкой проверить ссылки вида «в уроке N» во всех уроках, таблицу заданий в `app.js` и диапазоны разделов в `study/ПРАВИЛА.md`.
- **Кэш браузера.** После правки урока браузер может показать старую версию файла. У всех скриптов и стилей в `legacy/go-course/index.html` есть номер версии `?v=N` — **при каждом обновлении курса поднимать N на единицу**. Новый урок подключать сразу с текущим номером.
- **Ссылка на лестницу из курса** (`../ladder.html`) работает и при открытии двойным кликом, и на сервере `legacy`: его корень — папка `legacy/`.
