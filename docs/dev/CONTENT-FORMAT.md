# Формат контента

Два формата: **v0** — так устроен Go-курс сейчас, **v1** — цель этапа 1. Курс v0 переводится в v1 конвертером, руками ничего не переписывается.

## v0 — формат Go-курса

Курс — файл плана (`course.js`): разделы, список уроков с номерами, общий словарь. Плюс по файлу на урок:

```js
COURSE.lessons['interfaces'] = {
  time: '~30 мин',
  lead: 'лид',
  simple: ['абзац', '<b>Как сказать на собесе:</b> «…»'],
  blocks: [ { part: 'Название части' }, { p: '…' }, … ],
  hands: { title, goal, steps: [{ t, d, cmd, code, out, after }], trouble: [], check: [вопросы] },
  summary: ['главное', …],
  test: [вопросы],
  videos: [{ url, title, channel, dur, why, part }]
};
```

**Текст.** Разрешён простой HTML (`<b>`, `<i>`, `<code>`). Внутри текста:
- `{{ключ}}` или `{{ключ|текст}}` — термин из словаря;
- `{{>id}}` или `{{>id|текст}}` — ссылка на урок.

**Части.** Маркер `{ part: 'Название' }` в `blocks` начинает новую часть теории. «Сделай руками» и «Проверка» добавляются частями автоматически.

**Блоки:**

| Блок | Поля |
|---|---|
| заголовок | `{ h }`, `{ h3 }` |
| абзац, список | `{ p }`, `{ list, ordered }` |
| код | `{ code, cap, file }` |
| таблица | `{ table: { head, rows } }` |
| врезки | `{ note \| warn \| cs, title }` — `cs` выводится свёрнутой |
| схема | `{ scheme: { title, html, cap } }` |
| пошагово | `{ steps: { title, items: [{ t, d, code }] } }` |
| анимация | `{ anim: { title, w, h, els, steps, side, speed } }` |
| предскажи и запусти | `{ predict: { file, q, code, cmd, out, err, after, go } }` |

**Анимация.** Элементы: `box`, `tok`, `arrow`, `label`, `mark`. Шаг — `{ cap, set: { id: { x, y, show, cls, t, s } }, side }`. Состояние накапливается от шага 0. Классы: `hot`, `bad`, `ok`, `dim`, `mut`. Карточка состояния: `side: { title, rows: [[имя, значение, класс]] }`, шаг заменяет строки.

**Вопросы:**
- `{ type: 'choice', q, opts, a, why, part }`;
- `{ type: 'text', q, a: [варианты], why, part }`;
- `{ type: 'order', q, items, why, part }` — `items` в правильном порядке.

`part: N` делает вопрос блоком «Проверь себя» в части N. Часть засчитывается, когда на её вопросы ответили верно. Урок — когда решены все вопросы.

## v1 — формат платформы

Курс живёт версиями в базе и правится в админке; `content/<id>/course.json` — начальная загрузка и снимок в git ([0009](decisions/0009-database-is-the-source.md)). Код формата — `internal/course`, проверка — `citadel check`. Go-курс получен из v0 конвертером (`task convert`), и тест проверяет, что туда и обратно ничего не теряется.

**Курс — JSON-документ с паспортом:**

```json
{
  "schema": 1,
  "id": "go",
  "title": "Go: путь до senior",
  "subtitle": "От слайсов до system design — с объяснением «почему»",
  "metal": "iron",
  "tool": { "name": "Go", "version": "1.27", "file": "main.go", "cmd": "go run ." },
  "labels": { "section": "Раздел", "lesson": "Урок", "part": "Часть" },
  "review": [1, 3, 7],
  "pages": ["glossary", "notes", "exam", "tools"],
  "glossary": { "interface": { "t": "Интерфейс", "en": "interface", "d": "…" } },
  "root": [ …узлы… ]
}
```

`tool.version` обязательна: на этой версии получены все выводы программ в курсе. `tool.file` и `tool.cmd` — имя файла и команда запуска по умолчанию для блоков кода и «Предскажи» (у Go-курса `main.go` и `go run .`, у Postgres — `query.sql` и `psql -f query.sql`). `labels.cs` — подпись свёрнутой боковой врезки (`callout` вида `cs`): у Go-курса «Если ты из C#». `legacy: "v0"` — курс перенесён из прежнего движка, и на его странице есть перенос прогресса из него. `review` — интервалы карточек повторения в днях для оценок «Забыл», «С трудом», «Помню» ([0008](decisions/0008-first-attempt-and-cards.md)). `pages` — какие страницы справочника включены: `notes` (конспект), `glossary` (словарь), `exam` (контрольная); «Инструменты» — узел `page` с id `tools`. `about` — вступление на главной курса, `howto` — список «Как заниматься» там же (оба необязательны). `requires` — id курсов, на которые этот опирается: страница курса показывает их в «Опирается на», а сам курс попадает им в «Что дальше». `speech` — настройки озвучки (необязательно): `voice` — голос синтеза вида `ru-RU-SvetlanaNeural` (пусто — Светлана), `lexicon` — словарь произношения `{"Go": "гоу", "nil": "нил"}`: слово заменяется целиком и с учётом регистра. Сами записи в курс не входят — их делает сервис по опубликованному тексту (`docs/dev/AUDIO.md`).

У Go-курса `about`, `howto` и страницы курса берутся из `legacy/go-course/data/platform.js` (`COURSE.platform`): прежний движок держал эти тексты у себя в коде, теперь движок общий для всех курсов.

**Узел** — `{ id, kind, title, …, children | blocks }`:

| Поле | Что |
|---|---|
| `kind` | `section`, `lesson`, `part`, `page` |
| `n` | номер урока в курсе |
| `tag` | оформление раздела или карточки страницы (у Go-курса — `core`, `deep`, `backend`, `sd`) |
| `icon` | иконка страницы курса в меню (`code`, `book`, …) |
| `about` | описание раздела |
| `planned` | урок есть в плане, но ещё не написан: ни блоков, ни частей |
| `practice` | часть-практика: `hands` («Сделай руками») или `test` («Проверка») |
| `done` | правило прохождения. У части: без поля, `questions` или `hands` — когда решены её вопросы (без вопросов — когда дочитана); `read` — когда дочитана до конца, даже если вопросы есть; `manual` — кнопкой «Отметить часть пройденной». У урока: без поля — когда решены все его вопросы; `read` — когда закрыты все части, кроме итоговой проверки; `manual` — кнопкой «Отметить урок пройденным» в конце урока. «Дочитал» и «отметил» хранятся одной отметкой `seen` |
| `deps` | id узлов, на которые опирается |
| `time`, `lead`, `simple`, `say`, `summary`, `videos` | вступление и итог урока, как в v0 |

У узла либо `children`, либо `blocks`. Урок, разбитый на части, — это `children` из узлов `part`. Урок одной страницей — сразу `blocks`.

**Проект** ([0016](decisions/0016-projects.md)) — курс с `"type": "project"` в паспорте. Показывается своими страницами: `/projects` и `/p/<id>/`. В корне только уровни — узлы `section`: `tag` — сколько помощи (`guided`, `junior`, `ticket`), `about` — проблема уровня, `lead` — итог. Шаг — узел `lesson` с одним блоком `spec`, номер шага («1.2») считается по месту в дереве. `labels.lesson` — подпись шага в поиске, `labels.interview` — id уровня, с которого советуем ходить на собеседования, `howto` — правила: `<b>Заголовок</b>текст`. Новый проект при первой загрузке из `content/` закрыт, открывает его админ. Отметки: `done:<шаг>` — дата закрытия, `0` — вернули в работу; `seen:<шаг>:d<N>` — пункт «Готово, когда»; `seen:<шаг>:h<N>` — открытая подсказка; `seen:<шаг>:repo` — ссылка на коммит.

**Страница курса** — узел `page` в корне рядом с разделами: `{ id, kind: "page", title, icon, tag, lead, about, blocks }`. Появляется в меню курса, открывается по `#id`, рисуется теми же блоками, что и уроки. С `about` — ещё и карточкой на главной. Так у Go-курса устроен «Практикум».

**Блок** — `{ "type": "…", …поля }`. Тип — явное поле, а не «какой ключ есть», как в v0: так у блока есть тип для схемы и для модуля, который его рисует. Список типов и обязательных полей — `internal/course/blocks.go`, его же отдаёт `GET /api/blocks`.

| Тип | Поля | Из v0 |
|---|---|---|
| `heading` | `text`, `level` (2 или 3) | `{ h }`, `{ h3 }` |
| `text` | `html` | `{ p }` |
| `list` | `items`, `ordered` | `{ list, ordered }` |
| `code` | `code`, `cap`, `file` | `{ code, cap, file }` |
| `callout` | `kind` (`note`, `warn`, `cs`), `html`, `title` | `{ note \| warn \| cs, title }` |
| `table` | `head`, `rows` | `{ table: { … } }` |
| `scheme` | `title`, `html`, `cap` | `{ scheme: { … } }` |
| `steps` | `title`, `items` | `{ steps: { … } }` |
| `anim` | `title`, `w`, `h`, `els`, `steps`, `side`, `speed` | `{ anim: { … } }` |
| `predict` | `file`, `q`, `code`, `cmd`, `out`, `err` (`true` — вывод это ошибка), `after`, `ver` (версия, если вывод получен не на версии из паспорта) | `{ predict: { … } }` |
| `question` | `id`, `kind` (`choice`, `text`, `order`), `q`, `opts`, `a`, `items`, `why`, `exam` (`false` — не брать в контрольную) | элемент `test` |
| `hands` | `title`, `goal`, `steps`, `trouble`, `check` (вопросы с `id` и `kind`), `min` (сколько минут займёт; без него — 3 минуты на шаг) | `hands` урока |
| `embed` | `src` | — (место для песочницы) |
| `spec` | `task`, `done` (пункты «Готово, когда»; порядок не менять: отметки хранятся по номеру), `kind` (`incident`), `build`, `api` (`req`, `res`), `files`, `lessons` (`course`, `id`, `why` — текст врезки в уроке), `search`, `hints` (`title`, `text`, `code`), `traps`, `skip`, `viva` (`id`, `q`, `a`) | — (только в проектах) |

**Вопросы — тоже блоки.** «Проверь себя» стоит прямо в своей части, вопросы итоговой проверки — в части `practice: "test"`. Отдельного списка `test` с `part: N` больше нет.

**У каждого вопроса есть `id`**, уникальный в курсе: по нему хранится прогресс («решён»), и он не меняется, когда вопросы переставляют или добавляют. Конвертер даёт `урок.qN` вопросу `test[N-1]` из v0 и `урок.hN` вопросу `hands.check[N-1]` — так старый прогресс (по номеру в v0) переносится один в один. Новым вопросам — следующий свободный номер, старые id не переиспользовать.

**Текст** — как в v0: простой HTML, `{{термин}}`, `{{термин|текст}}`, `{{>id}}`, `{{>id|текст}}`. Проверка ловит ссылки на несуществующие термины и узлы.

**Проверка курса** (`citadel check`, она же при старте сервера, при сохранении в редакторе и перед публикацией — версию с ошибками сервер не публикует): версия схемы, паспорт, уникальные id, виды узлов, известные типы блоков и их обязательные поля, ссылки на термины и узлы, `deps`, у вопроса с выбором верный индекс в границах, у вопроса на порядок не меньше двух пунктов, у «предскажи» есть вывод или ошибка.

**Модуль блока.** Схему полей и проверку держит сервер (`internal/course/blocks.go`), всё остальное — модуль в движке (`web/static/engine/blocks/`): объект `{ type, render(block, ctx), speak(node, block), questions(block) }`. `render` рисует блок, `speak` отдаёт элементы для озвучки, `questions` — вопросы, от которых зависит выполнение части. Модули регистрируются в `blocks/index.js`. Неизвестный тип рисуется заглушкой. В редакторе (`web/static/admin/blocks.js`) у простых блоков своя форма, сложные правятся как JSON; новый тип без формы тоже правится как JSON.

Новый тип блока — это: запись в `internal/course/blocks.go`, модуль в `web/static/engine/blocks/`, строка в `blocks/index.js`, строка в таблице выше, заготовка в `newBlock` редактора и, если нужно, форма в `FORMS`.

**Миграции.** `schema` — версия формата. Изменение блока = новая версия + функция миграции; сервер переводит курсы при загрузке.
