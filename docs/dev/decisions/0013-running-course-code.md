# 0013. Запуск кода курсов на сервере

Дата: 2026-10-30 · Статус: принято (владелец согласился 30.10, сделано 31.10)

## Контекст

Правило курсов: каждый вывод программы получен запуском, а не из памяти. Сейчас автор или агент запускает код у себя, а сервер проверяет только, что вывод в блоке есть. Владелец решил (30.10): запуск на сервере нужен, но с учётом безопасности. В макетах — «Запустить снова» у «Предскажи» в редакторе и «вывод подтверждён запуском» в очереди правок агентов.

Запускать чужой код на домашнем сервере владельца — самое опасное, что умеет сервис. Поэтому сначала модель угроз, потом устройство.

## Модель угроз

**Откуда придёт вредный код.** Правка агента — агент мог прочитать внедрённую инструкцию где угодно (решение 0003 исходит из этого); утёкший токен агента; импорт чужого курса; ошибка самого админа (бесконечный цикл, `fork`-бомба по неосторожности).

**Чего хочет атакующий, по убыванию вреда:**
1. Выбраться на хост: домашний сервер, его диски, Docker.
2. Достать секреты: `.env` (код доступа), базу SQLite, токены, сессии.
3. Сеть: ходить в домашнюю сеть (роутер, NAS, другие устройства), в интернет — скачать вредонос, выгрузить данные, атаковать кого-то от имени владельца.
4. Достучаться до самого Citadel изнутри: API, админка.
5. Положить сервер: память, процессор, процессы, диск, бесконечный вывод.

**Кто может запускать.** Только админ (в редакторе) и агенты с правом «предлагать правки» (проверка своей правки). Ученики — никогда: им показывается уже сохранённый вывод.

## Решение

**Каждый запуск — отдельный одноразовый контейнер**, который создаётся под один запуск и удаляется после:

| Угроза | Защита |
|---|---|
| Сеть: домашняя сеть, интернет, Citadel | `--network none`: у контейнера нет сетевого интерфейса, кроме loopback |
| Секреты и база | Никаких томов и монтирований: код приходит в переменной окружения и пишется во временный диск в памяти. Ни тома `citadel-data`, ни `.env`, ни переменных окружения Citadel |
| Выход на хост | Непривилегированный пользователь (uid 65534), `--cap-drop ALL`, `--security-opt no-new-privileges`, профиль seccomp Docker по умолчанию, корневая ФС только для чтения (`--read-only`) |
| Память, процессы | `--memory 768m --memory-swap 768m` (временный диск считается в той же памяти), `--pids-limit 64`, не больше 256 открытых файлов — `fork`-бомба упирается в лимит |
| Процессор, время | `--cpus 1`, жёсткий таймаут: сборка + запуск 60 с, потом контейнер убивается. Сборка без кеша: программа с `fmt` — около 7 с, с `net/http` — около 20 с на одном ядре |
| Диск | Рабочая папка, кеш сборки и `/tmp` — `tmpfs` на 384 МБ (кеш сборки `net/http` — около 90 МБ плюс промежуточные файлы); файл не больше 64 МБ; на диск хоста ничего не пишется. Логи контейнера ограничены 1 МБ |
| Бесконечный вывод | Вывод идёт через `head -c 65536`: после 64 КБ программа получает SIGPIPE и завершается, в результате — «вывод обрезан» |
| Очередь запусков | Не больше одного запуска одновременно на токен или админа и двух на весь сервер; остальное — «занято, повтори» |

**Кто создаёт контейнеры.** Сам Citadel к Docker не ходит. Отдельный маленький сервис `citadel runner` (тот же бинарник, другая команда) принимает от Citadel запрос «запусти этот код на Go 1.27» по внутренней сети с общим секретом из `.env` и создаёт контейнер через Docker API. Доступ runner к Docker — не сокет целиком, а через прокси сокета (`docker-socket-proxy`), где разрешены только операции с контейнерами: создать, запустить, дождаться, прочитать вывод, удалить. Образы, тома, сети, `exec` и всё остальное закрыты. Runner не публикует портов наружу.

**Что запускается.** Набор инструментов задаётся по `tool` паспорта курса: для `Go` — образ `golang:1.27-alpine`, команда `go run <файл>`; имя файла — из блока или `tool.file`, только латиница, цифры, `_`, `-` и одно расширение. Поле `cmd` блока не исполняется никогда: команду задаёт набор инструментов. Кеш сборки каждый раз пустой — общий кеш между запусками стал бы каналом, через который один запуск влияет на другой. Для курса без набора инструментов кнопка «Запустить» не показывается. PostgreSQL — второй этап: ему нужен живой сервер БД внутри одноразового контейнера, это отдельная доработка.

**Где видно результат.**
- В редакторе у «Предскажи и запусти» кнопка «Запустить на сервере»: вывод показывается рядом с сохранённым, различия подсвечиваются, «Подставить вывод» заменяет `out` (и ставит `err`, если код выхода не ноль). Видна версия, на которой получен вывод (`Go 1.27.3`). Отдельного поля «проверено» в блоке нет: формат блока не менялся.
- В очереди правок агентов сервер в фоне прогоняет каждый «Предскажи», который правка добавила или изменила (до 8 блоков), и показывает по каждому: совпал вывод / другой (с разницей) / не запустилось. Сравнение — без хвостовых пробелов и пустых строк в конце. Агенту доступен инструмент `run_code`, чтобы проверить код до отправки.

## Почему не иначе

- **Запускать в контейнере самого Citadel или в долгоживущем контейнере-исполнителе.** Код делил бы процесс-соседа, файловую систему и сеть с сервисом: прочитал бы базу или отправил запрос в Citadel изнутри. Одноразовый контейнер без сети и томов закрывает это целиком.
- **Отдать Citadel сокет Docker напрямую.** Доступ к сокету Docker равен root на хосте. Если Citadel взломают через веб, взломщик получит хост. Поэтому сокет — только у runner, и только через прокси с белым списком.
- **gVisor (`runsc`) сразу.** Самая сильная изоляция: ядро в пространстве пользователя, побег через уязвимость ядра хоста практически закрыт. Но требует установки на хост и не работает на Docker Desktop под Windows. Решение: runner умеет запускать с `--runtime runsc`, если он есть (`CITADEL_RUNNER_RUNTIME=runsc`), и это рекомендовано для домашнего сервера.
- **Запуск в браузере (WebAssembly).** Go-код с `os`, горутинами и паниками в браузере ведёт себя иначе, чем `go run` — вывод не будет «полученным запуском на версии из паспорта».
- **Сторонний песочный сервис (Go Playground и т. п.).** Код курсов уходил бы наружу, версия Go не наша, и сеть сервиса пришлось бы открыть в интернет.

## Остаточные риски

- **Уязвимость ядра.** Контейнер делит ядро с хостом; эксплойт ядра может вывести на хост. Снижается gVisor на домашнем сервере и своевременными обновлениями ядра и Docker.
- **Runner и прокси сокета** — самые ценные цели: через них можно создавать контейнеры. Они не видны снаружи, runner принимает запросы только с секретом, прокси закрывает всё, кроме операций с контейнерами. Но прокси проверяет пути API, а не поля запроса: тот, кто захватит сам runner, сможет создать привилегированный контейнер. Поэтому runner маленький, сам собирает конфигурацию контейнера и не принимает её от Citadel — Citadel передаёт только код, имя файла и имя набора инструментов.
- **Нагрузка.** Даже в лимитах запуск отъедает одно ядро до минуты; лимит параллельных запусков держит сервер отзывчивым.
- **Скорость.** Без общего кеша каждая сборка холодная: 7–20 секунд. Ускорить можно образом с заранее собранной стандартной библиотекой — когда это начнёт мешать.

## Проверено (31.10, Docker Desktop)

Программы-атаки, запущенные через runner:

- Сеть: запросы к `citadel`, `runner`, `docker-proxy`, `1.1.1.1`, `host.docker.internal` — все падают; из интерфейсов есть только `lo`.
- Сокета Docker и `/app/data` в контейнере нет; запись в `/usr/local` запрещена; uid и gid — 65534; `CapEff: 0`, `NoNewPrivs: 1`, seccomp включён; из переменных окружения — только код и настройки сборки.
- `fork`-бомба: остановилась на 51 процессе. Память: процесс убит после 640 МБ. Поток вывода: обрезан на 64 КБ. Бесконечный цикл: снят по таймауту через 60 с. Ни одного контейнера после запусков не осталось.
- Прокси: `images`, `volumes`, `networks`, `info`, создание тома — 403. Citadel до прокси не достаёт, у runner нет выхода в интернет.

## Последствия

- В `compose.yaml` появляются сервисы `runner`, `docker-proxy` (`tecnativa/docker-socket-proxy:0.3.0`) и `go-toolchain` (только скачивает образ Go); в `.env` — `CITADEL_RUNNER_SECRET`. Без них Citadel работает как сейчас, кнопки запуска просто не показываются.
- Домашний сервер: рекомендуется поставить gVisor и включить `CITADEL_RUNNER_RUNTIME=runsc`; инструкция — в `docs/guides/self-hosting.md`.
- Образ набора инструментов (`golang:1.27-alpine`, ~250 МБ) скачивается один раз при установке.
