# 0012. Доступ к курсам: публичный и приватный

Дата: 2026-10-30 · Статус: принято. Уточнено решением [0023](0023-course-authors.md): курс видит и его владелец-автор.

## Контекст

До этапа 8 любой вошедший видел все опубликованные курсы. Владелец хочет делать курсы как публичные, так и приватные; группы пользователей — когда понадобятся, сейчас их нет. В макете «Пользователи» есть столбец «Курсы».

## Решение

- У курса есть настройка доступа: `public` — видят все вошедшие, `private` — видят админы и пользователи, которым курс выдан. По умолчанию — `public`.
- Доступ — настройка сервиса, а не содержимое курса: он хранится в базе (`courses.access`, таблица `course_access`), а не в JSON курса. Поэтому импорт, правки агентов и откат версий его не меняют.
- Переключатель — в «Курсах» админки, выдача приватных курсов пользователю — в «Пользователях» (столбец «Курсы», «изменить»). Если сделать курс снова публичным, выданный доступ сохраняется и вернётся, когда курс опять станет приватным.
- Закрытый курс для пользователя выглядит как несуществующий: страница и API курса отвечают 404, его нет в каталоге, среди плиток «Скоро», в сводке, повторениях и поиске; прогресс по нему не читается и не пишется.
- Токены агентов доступом пользователей не ограничиваются: у токена своё ограничение по курсам ([0010](0010-agent-api-and-mcp.md)).

## Почему не иначе

- **Флаг в паспорте курса.** Тогда доступ ехал бы вместе с курсом через импорт и правки агентов, а агент мог бы открыть курс своей правкой.
- **Группы сразу.** Пока людей кроме владельца нет, группа из одного человека — лишняя сущность. Таблица `course_access` по пользователю расширяется до групп добавлением ещё одной таблицы.
- **403 вместо 404 для закрытого курса.** 403 сообщает, что курс существует; для приватного курса это лишнее.

## Последствия

- Каждый запрос к курсу читает выданные пользователю курсы (один запрос к SQLite); админам — без запроса.
- Прогресс по курсу, который закрыли, в базе остаётся и снова виден, если доступ вернуть.
