# 0022. Аккаунты: логин и пароль, приглашения, сброс пароля

Дата: 2026-11-12 · Статус: принято. Заменяет вход из [0007](0007-sign-in-and-progress-sync.md).

## Контекст

Сейчас вход — это имя плюс общий код `CITADEL_ACCESS_CODE`, а роль админа выдаёт список `CITADEL_ADMINS` при каждом входе ([0007](0007-sign-in-and-progress-sync.md)). Пароля у человека нет. Любой, кто знает код, войдёт под любым именем, в том числе под именем админа. Понизить такого админа в админке нельзя: при следующем входе список вернёт ему роль. Удалить или заблокировать человека тоже нельзя.

В 0007 это сознательно отложили «до людей кроме владельца». Теперь такие люди есть: владелец пускает знакомого, который будет делать свои курсы ([0023](0023-course-authors.md)). Публичной регистрации владелец не хочет. Ему нужна управляемая: по ссылкам из админки, как в Fluxer и Discord.

## Решение

### Аккаунт

- **Логин** — для входа: `^[a-z0-9][a-z0-9._-]{2,31}$`, без учёта регистра (сохраняется в нижнем регистре), уникальный.
- **Имя** — для отображения: правила прежние (1–40 букв, цифр, пробелов, `.-_`), уникальное, как сейчас. Человек меняет его в профиле.
- **Пароль** — от 10 до 256 символов, без правил «заглавная плюс цифра». Совпадать с логином не может. Хранится хэш argon2id (`golang.org/x/crypto/argon2`, m=19 МиБ, t=2, p=1) строкой PHC: `$argon2id$v=19$m=19456,t=2,p=1$<соль>$<хэш>`. Параметры записаны в строке, поэтому их можно поднять позже без миграции.
- **Блокировка** вместо удаления. У заблокированного прогресс остаётся, а сессии, ссылки сброса и токены агентов перестают работать сразу.

Миграция `users`: столбцы `login` (уникальный, `COLLATE NOCASE`, может быть пустым до первой настройки), `password_hash`, `disabled_at`, `invite_id`. Тем, у кого имя подходит под правила логина, миграция ставит логин = имя в нижнем регистре. Остальным логин задаёт админ.

### Вход

- `/login`: логин, пароль, «Запомнить меня» (как сейчас: 180 дней или 24 часа).
- На любую ошибку один ответ: «Логин или пароль не подошли». По нему нельзя узнать, существует ли логин. Для несуществующего логина хэш всё равно считается, чтобы время ответа не выдавало разницу.
- Ограничение попыток: прежнее по IP (10 за 10 минут) плюс по логину (10 за 15 минут).
- `UserBySession` не пускает заблокированного. Роль читается из базы при каждом запросе, поэтому смена роли действует сразу.
- `CITADEL_ACCESS_CODE` и `CITADEL_ADMINS` больше не читаются. Если они заданы, сервер пишет в лог предупреждение: «переменная больше не используется, см. 0022».

### Приглашения

Админ создаёт ссылку `<адрес>/join/<код>` во вкладке «Приглашения» и задаёт:

| Поле | Варианты |
|---|---|
| Пометка | свободный текст: «для Саши» |
| Роль | ученик или автор. Админа приглашением не создать: его назначают вручную |
| Курсы | какие закрытые курсы выдать сразу при регистрации |
| Сколько раз | один раз · N раз · без ограничения |
| Срок | 1 час · 1 день · 7 дней · 30 дней · до даты · бессрочно |

- Код — 16 случайных байт в base64url. Хранится в базе открыто, и ссылку можно скопировать в любой момент, как в Fluxer. Риск ограничен: у ссылки есть срок и число использований, её можно отозвать, и она создаёт новый аккаунт, а не открывает существующий.
- Таблица `invites`: `id, code UNIQUE, note, role, courses, max_uses (NULL — без ограничения), uses, expires_at (NULL — бессрочно), created_by, created_at, revoked_at`.
- Статус в списке: активна, исчерпана, истекла, отозвана. Рядом — «использована 2 из 5» и кто по ней зарегистрировался (`users.invite_id`). Отозвать можно любую ссылку, удалить — только неактивную.
- Страница `/join/<код>` открывается без входа. Если ссылка рабочая, на ней видно, что человек получит («Роль: автор. Курсы: …»), и форма: логин, имя, пароль дважды. Если ссылка не работает, страница объясняет почему, но не показывает чужую пометку и курсы. Тому, кто уже вошёл, страница предлагает выйти, прежде чем регистрировать новый аккаунт.
- Регистрация — одна транзакция: проверить ссылку, создать пользователя с ролью, выдать курсы (только существующие), увеличить `uses`, создать сессию. Две регистрации одновременно по одноразовой ссылке не пройдут обе. Ограничение по IP — как у входа.

### Сброс и смена пароля

- **Сам человек** меняет пароль в профиле: старый пароль и новый дважды. Остальные его сессии закрываются, текущая остаётся. Там же кнопка «Выйти на всех устройствах».
- **Админ** нажимает у пользователя «Ссылка для сброса пароля» и получает одноразовую ссылку `<адрес>/reset/<токен>` на 24 часа. Ссылка показывается один раз: в отличие от приглашения, она открывает существующий аккаунт. Новая ссылка отменяет прежние. По ссылке человек задаёт пароль сам, админ его не узнаёт. После сброса закрываются все сессии этого человека. Таблица `password_resets`: `token_hash, user_id, created_by, created_at, expires_at, used_at`. В базе только SHA-256, как у сессий.
- Если у пользователя ещё нет логина (старый аккаунт с кириллическим именем), админ задаёт логин в том же окне.

### Консоль: если владелец сам потерял доступ

Команды работают напрямую с базой (`CITADEL_DATA`, как у `serve`), поэтому в контейнере их можно запустить из консоли Portainer или так: `docker exec -it citadel citadel user …`.

| Команда | Что делает |
|---|---|
| `citadel user list` | id, логин, имя, роль, заблокирован ли |
| `citadel user reset-password <логин>` | ставит случайный пароль (20 символов), печатает его, закрывает все сессии |
| `citadel user reset-password --id <id> --login <логин>` | то же для старого аккаунта без логина, заодно задаёт логин |
| `citadel user add --role admin --name <имя> <логин>` | создаёт пользователя, печатает пароль |
| `citadel user set-role <логин> admin\|author\|student` | меняет роль |
| `citadel user unblock <логин>` | снимает блокировку |

Пароль печатается только в консоль и в лог не пишется. Если при старте сервера нет ни одного админа с паролем, сервер пишет в лог подсказку: `no admin can sign in: run "citadel user reset-password <login>" or "citadel user add --role admin …"`.

**Переход на сервере владельца:** обновить образ и выполнить в консоли контейнера `citadel user list`, затем `citadel user reset-password <логин>` (или с `--id`, если логин не проставился). Дальше войти с напечатанным паролем и сменить его в профиле.

### Админка: «Пользователи»

- Столбцы: имя, логин, роль (список: ученик, автор, админ), курсы (чипы, «изменить»), откуда пришёл (пометка приглашения), когда был, статус.
- Действия: ссылка для сброса пароля, заблокировать или разблокировать.
- Себя нельзя заблокировать или понизить. Последнего админа нельзя понизить или заблокировать.
- Выдача доступа с другой стороны: в «Курсах» у закрытого курса стоит «Видят: 3 — изменить», и открывается список пользователей с галочками и поиском (`PUT /api/admin/courses/{id}/users`).

### Журнал действий

Таблица `audit`: `at, actor, action, target, details` (JSON). Записываются смена роли, блокировка и разблокировка, ссылка сброса, сброс из консоли (`actor` = `console`), создание и отзыв приглашения, регистрация по приглашению, выдача курсов, смена владельца курса и доступа к нему ([0023](0023-course-authors.md)), выпуск и отзыв токенов. Вкладка «Журнал» в админке видна только админу: последние 200 записей с фильтром по типу. Пароли, коды и токены в журнал не попадают.

## Почему не иначе

- **Оставить общий код и добавить к нему пароль.** Два секрета на вход ничего не дают, если пароль есть у каждого.
- **Почта для сброса и подтверждения.** Нужен свой SMTP или сторонний сервис ради нескольких человек. Сброс через админа и консоль закрывает задачу.
- **Админ задаёт временный пароль.** Тогда админ знает чужой пароль, а человек часто его не меняет. Временный пароль остаётся только в консоли, на случай, когда админ — сам владелец.
- **bcrypt.** Тоже подходит, но обрезает пароль до 72 байт. argon2id — текущая рекомендация OWASP, и он из той же `x/crypto`.
- **Показывать приглашение один раз, как токен.** Безопаснее при утечке базы, но владелец хочет пересылать ссылку повторно. А тот, у кого есть база, и так видит всё остальное.
- **Удаление пользователя.** Теряется прогресс, а связи (версии с автором, журнал, приглашения) повисают. Блокировка обратима. Удаление можно добавить позже.
- **OAuth через GitHub или Google.** Зависимость от внешнего сервиса и регистрация приложения ради нескольких знакомых.

## Последствия

- Новая зависимость: `golang.org/x/crypto`.
- Знакомым больше не нужен общий код. Каждому — своя ссылка, и каждого можно заблокировать.
- Двухфакторной защиты нет. Понадобится, если появятся люди, которых владелец не знает лично.
- Руководство `docs/guides/self-hosting.md` и `.env.example` переписываются: вместо кода и списка админов — первая команда `citadel user add --role admin`.
