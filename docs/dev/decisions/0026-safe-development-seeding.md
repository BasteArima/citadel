# 0026. Защита личной базы от dev-seed

Дата: 2026-11-17 · Статус: принято

## Контекст

Команда тестовых данных из этапа каталога ([0024](0024-course-directions.md)) разрешала заменять любую базу флагом `-force`, даже в папке `data`. Ошибка пути могла уничтожить личные или боевые данные.

## Решение

Всегда запрещать целевую папку с именем `data`, без учёта регистра. Флаг `-force` разрешает замену только базы, созданной `dev-seed`. При создании команда сохраняет в SQLite `application_id = 0x43495444` (`CITD`). Обычное открытие хранилища эту метку не ставит.

Проверять метку отдельным подключением `mode=ro&immutable=1`, до удаления базы и её файлов WAL/SHM. Не запускать миграции и не создавать вспомогательные файлы при проверке. Если база не читается или метки нет, отказывать. Не использовать наличие `dev-login.txt`, имена аккаунтов или курсов как признак тестовой базы. При отсутствии основного файла базы, но наличии WAL/SHM, тоже отказывать.

## Почему не иначе

Имя папки само по себе не защищает личную базу, расположенную в другом каталоге. Файл рядом с базой можно случайно сохранить при её замене. Встроенное поле SQLite хранится внутри самой базы и не требует таблиц или миграции схемы платформы.

Проверка намеренно игнорирует WAL: если метка ещё не сохранена в основном файле, замена запрещена. Перед пересозданием тестовых данных сервер разработки должен быть остановлен.

## Последствия

Новые тестовые базы можно пересоздавать привычным `task seed-dev`. Старые базы без метки автоматически тестовыми не считаются: для следующего запуска нужно выбрать другую пустую папку. Тесты проверяют запрет `data` даже с меткой, отказ для обычной, старой и повреждённой базы, сохранность файлов и успешную замену базы `dev-seed`.
