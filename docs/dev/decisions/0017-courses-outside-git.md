# 0017. Курсы владельца не лежат в git и в образе

Дата: 2026-11-01 · Статус: принято. Уточняет [0009](0009-database-is-the-source.md).

## Контекст

Курсы владельца личные: он пишет их для себя и публиковать не собирается. Они оказались в публичном репозитории, потому что `content/` и `legacy/go-course/` были в git, а `Dockerfile` копировал `content/` в образ. Владелец хочет поднимать сервис из образа, собранного в GitHub.

## Решение

- `content/` и `legacy/go-course/` — в `.gitignore`, файлы остаются только на ПК владельца. Историю git не переписываем: владелец решил, что прошлые коммиты его не волнуют.
- В репозитории и образе есть только тестовый курс и тестовый проект — `content-demo/`.
- Образ собирает GitHub Actions при пуше в `main` и публикует в `ghcr.io/bastearima/citadel`.
- На сервер курсы попадают через «Импорт JSON» в админке, а дальше живут в базе (0009). Стек для Portainer тестовый курс не загружает.
- Скриншоты в README снимаются на тестовом курсе.

## Почему не иначе

- **Приватный репозиторий и приватный образ.** Курсы всё равно лежали бы на GitHub, а серверу понадобился бы токен для скачивания образа.
- **Образ без GitHub, файлом.** Работает, но каждое обновление требует ручной сборки и загрузки.

## Последствия

- Файлы курсов есть только на ПК владельца и в базе. Бэкап базы теперь важен и для самих курсов.
- На чистой копии тесты конвертера Go-курса пропускаются.
- Чтобы `task up` загружал свои курсы, в `.env` нужна строка `CITADEL_CONTENT_DIR=./content`.
