# 0005. Конвертер v0 исполняет JS, движок пока читает v1 через переходник

Дата: 2026-10-29 · Статус: принято; переходник удалён по решению [0006](0006-engine-modules-and-question-ids.md), круговой тест конвертера теперь обходится без него

## Контекст

Go-курс v0 — это JS-файлы, которые наполняют `window.COURSE`: литералы объектов с одинарными кавычками, комментариями и ключами без кавычек. Его нужно перевести в v1 без потерь и показать с сервера так же, как раньше. Прежний движок (`app.js`, ~1200 строк) понимает только модель v0.

## Решение

- Конвертер (`internal/legacy`) исполняет файлы курса во встроенном JS-интерпретаторе goja в том порядке, в каком их подключает `index.html`, и берёт готовый `window.COURSE`. Каждый блок переводится строго: незнакомое поле — ошибка.
- Первый шаг перевода движка: `app.js` не меняется, перед ним стоит переходник `adapter.js`, который превращает v1 из API обратно в модель v0.
- Тест гоняет курс по кругу: v0 → конвертер → v1 → переходник (в том же goja) → v0 — и сравнивает с оригиналом. Сравнение текста страниц в браузере у прежнего и нового движка совпало на всех маршрутах.

## Почему не иначе

- **Разбирать JS-литералы самим.** Хрупко: комментарии, кавычки, строки с `}` внутри. Интерпретатор понимает файл ровно так же, как браузер.
- **Конвертировать через Node.** Ещё одна зависимость для сборки и тестов; goja — обычный Go-модуль.
- **Сразу переписать движок на v1 и модули блоков.** Одним шагом нельзя проверить, что курс не сломался: две перемены сразу. Переходник даёт точку сравнения «как было».

## Последствия

- Переходник временный: на шаге 2 пункта 1.6 движок читает v1 сам, переходник и круговой тест через него удаляются.
- Пока работает правило прохождения v0, поле `done` у узлов не используется.
- Порядок вопросов «Проверка» в модели движка может отличаться от v0: v1 группирует их по частям. Для импорта старого прогресса (этап 2) вопросы сопоставляются по содержимому, а не по номеру.
