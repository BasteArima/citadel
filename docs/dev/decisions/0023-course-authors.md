# 0023. Роль автора: свои курсы, свои агенты

Дата: 2026-11-12 · Статус: принято. Уточняет [0012](0012-course-access.md), [0019](0019-agent-reviewer.md) и [0020](0020-reviewer-own-proposals.md). Требует [0021](0021-course-html-filter-and-csp.md) и [0022](0022-accounts-passwords-invites.md).

## Контекст

Ролей две: ученик и админ. Создавать и править курсы может только админ, и он может всё: чужие курсы, пользователей, токены. Владелец пускает знакомого, который хочет делать свои курсы для себя, в том числе с помощью своей нейросети через токен агента. Давать ему админа нельзя: он сможет сломать чужие курсы и увидит всех пользователей. Нужна роль между учеником и админом.

## Решение

### Роли

| | Ученик | Автор | Админ |
|---|---|---|---|
| Видит курсы | публичные и выданные | публичные, выданные и свои | все |
| Админка | нет | «Мои курсы», «Агенты» и «Озвучка» — только по своим курсам | всё |
| Создаёт курсы | нет | да, в пределах лимита | да |
| Правит, публикует, откатывает, удаляет | нет | свои курсы | любые |
| Запуск кода в редакторе | нет | в своих курсах | да |
| Озвучка | слушает | записывает для своих курсов | да |
| Токены агентов | нет | свои, действуют только на его курсы | любые |
| Доступ к курсу (публичный, кому выдан) | нет | нет | да |
| Пользователи, приглашения, журнал | нет | нет | да |

Роль `author` выдаёт админ: в «Пользователях», приглашением ([0022](0022-accounts-passwords-invites.md)) или командой `citadel user set-role`.

### Владелец курса

- `courses.owner_id` — ссылка на пользователя, может быть пустой. У всех нынешних курсов он пустой: это «курсы платформы», их правит только админ.
- Курс, созданный автором (в редакторе, «Импортом JSON» или его агентом), принадлежит автору.
- Новый курс автора по умолчанию **закрытый**. Его видят автор и админы. Сделать курс публичным или выдать его другим может только админ: курс автора не появится в каталогах других без ведома владельца сервиса.
- Админ может передать курс другому автору или платформе («Курсы» → «Владелец»). Действие пишется в журнал.
- Видимость курса — одно правило для каталога, страницы курса, API, поиска, повторений, сводки, проектов и озвучки (`visible()` в `server.go`): `админ || владелец || публичный || выдан`.
- Автор, которого понизили до ученика, продолжает видеть свои курсы, но править их не может. Его токены перестают работать.
- id курса общий для всего сервиса. Если автор выбрал занятый id, он получает ошибку «id занят», и чужой курс не перезаписывается. «Импорт JSON» поверх существующего id разрешён только для своего курса.
- **Лимит:** по умолчанию 10 курсов и проектов на автора. Админ меняет лимит в «Пользователях» (`users.course_limit`, пустое значение — 10). Лимит защищает от агента, который пошёл вразнос.

### Админка для автора

Страница та же, `/admin`. Сервер в `/api/me` отдаёт роль, и интерфейс показывает вкладки по ней. Защиту даёт не интерфейс, а сервер:

- Вместо одного `s.admin(…)` будут две обёртки: `s.admin(…)` — только админ (пользователи, приглашения, журнал, доступ, владелец), `s.staff(…)` — админ или автор.
- Каждый маршрут с `{id}` курса под `s.staff` проверяет `canEdit(user, course) = админ || владелец` и отвечает 404 для чужого курса, а не 403, как в [0012](0012-course-access.md).
- Списки (курсы, правки агентов, токены, озвучка) автор получает уже отфильтрованными сервером.
- Тесты на каждый маршрут: автор не читает и не меняет чужой курс, чужую правку и чужой токен.

### Агенты автора

- `tokens.user_id` — кто выпустил токен. У старых токенов поле пустое, они считаются токенами админа.
- Токен работает, только пока его владелец не заблокирован и остаётся автором или админом. Проверка идёт при каждом запросе.
- Доступ токена автора = курсы из ограничения токена (или «все»), пересечённые с курсами, которыми автор владеет сейчас. Курс, переданный другому, выпадает из доступа сразу.
- Право «создавать курсы» у токена автора создаёт курсы с владельцем-автором и в пределах его лимита.
- Право проверяющего автор может включить своему токену. Оно действует на его курсы: публиковать их он и так может сам. Правку с несовпавшим выводом программы, которую по [0019](0019-agent-reviewer.md) решает «только админ», для курса автора решает владелец курса или админ.
- **Токен админа с доступом ко «всем курсам» не видит курсы авторов.** «Все» теперь значит «курсы платформы и свои». Курс автора попадает в токен админа, только если его выбрали явно. Причина: текст чужого курса — данные, а агенту владельца незачем читать то, что написал чужой агент. Так меньше места для внедрённых инструкций.
- Окно «Подключить агента» в админке автора работает так же: с командами для Claude Code, Codex и других.

### Озвучка

Автор записывает озвучку своих курсов: раздел «Озвучка», словарь произношения, «послушать». Задачи записи у всех общие: одна очередь, одна задача за раз, как сейчас ([0015](0015-narration-recorded-by-server.md)). Длинная запись автора может задержать запись владельца. Пока людей мало, это приемлемо (решение владельца 12.11.2026).

### Каталог

У автора его закрытые курсы стоят в каталоге с пометкой «Только у тебя». Неопубликованный курс виден в «Мои курсы» админки, а в каталоге — нет, как и у админа.

## Почему не иначе

- **Права на курс вместо роли** (редактор конкретного курса, как в Google Docs). Гибче, но это таблица прав, интерфейс приглашения на курс и вопросы вроде «кто может удалить». Сейчас один автор и только свои курсы. Владелец курса закрывает задачу, а права можно добавить позже поверх `owner_id`.
- **Автор сам открывает и раздаёт свои курсы.** Тогда ему нужен список всех пользователей, и курс может попасть к людям владельца без его ведома. Если автору понадобится делиться, следующий шаг — его собственные приглашения на его курсы.
- **Отдельная админка для автора.** Дублировался бы редактор, версии, очередь и озвучка. Одна страница с вкладками по роли и проверками на сервере проще поддерживать.
- **Назвать роль «модератор».** Модератор следит за чужим контентом, а здесь человек делает свой.
- **Выключить озвучку авторам.** Так предлагалось сначала, чтобы не нагружать сервер. Владелец решил включить: пользователей мало.

## Последствия

- Каждый новый маршрут админки теперь требует решения: `admin` или `staff` с `canEdit`. Это правило попадает в `ARCHITECTURE.md`.
- Курсы авторов не попадают в бэкап по `content/`: они живут только в базе, как и все курсы ([0009](0009-database-is-the-source.md)). Бэкап базы их сохраняет.
- Поделиться курсом автор может только через админа. Понадобятся приглашения автора — отдельное решение.
- Запуск кода и озвучка расходуют ресурсы сервера и по запросам автора. Если станет тесно — лимиты на автора.
