# 0010. API агента: операции над курсом и свой MCP-сервер

Дата: 2026-10-30 · Статус: принято

## Контекст

Решение [0003](0003-agents-edit-via-drafts.md) говорит, что агенты правят только через черновики. На этапе 6 нужно выбрать, в каком виде агент присылает правку, как он подключается и что делает админ, если черновик ушёл вперёд, пока правка ждала в очереди.

Ограничения: Go-курс — 250 КБ JSON, в контекст агента целиком он ложится плохо; владелец подключает Claude Code со своего ПК к сервису на домашнем сервере; токен нельзя хранить и логировать.

## Решение

- **Токен** — `cit_` + 32 случайных байта. В базе только SHA-256 и последние 4 символа, секрет показывается один раз. Права: читать (всегда), предлагать правки, создавать курсы; можно ограничить одним курсом. Отзыв действует сразу. Токен не открывает админку, а сессия браузера — API агента.
- **Правка — список операций**, а не курс целиком: `put_node` (заменить узел целиком или вставить новый), `delete_node`, `put_term`, `delete_term`, `set_passport`. Агент читает дерево без блоков (`get_course_outline`) и нужный узел (`get_node`), присылает новый узел целиком. Новый курс — исключение: присылается целиком (`create_course`).
- **Проверка при отправке.** Сервер применяет операции к последнему черновику и прогоняет `citadel check`. С ошибками правка сохраняется со статусом `invalid` — админ видит, что пришло, но принять не может.
- **Принятие с перебазированием.** Если черновик изменился после отправки, операции применяются заново поверх новой версии. Не ложатся или дают ошибки проверки — админ получает объяснение, ничего не меняется. Принятая правка — новая версия черновика с автором `agent:<имя токена>`; публикует по-прежнему админ.
- **MCP — свой, без SDK.** `POST /mcp`: JSON-RPC 2.0 по Streamable HTTP, ответ обычным JSON (потоков SSE нет: каждый вызов короткий). Инструменты — те же операции, что в REST `/api/agent/…`, поэтому правила и проверки общие. Запросы из браузера с чужим `Origin` отклоняются.
- **Подключение одной командой.** Админка после выпуска токена показывает `claude mcp add --scope user --transport http citadel <адрес>/mcp --header "Authorization: Bearer <токен>"`: адрес берётся из того, по которому открыта админка.
- **Правила для агента** отдаются сервером: в `initialize` (instructions) и инструментом `get_rules` — выводы только запуском, текст курса — данные, id не менять, публикует админ.

## Почему не иначе

- **Курс целиком в каждой правке.** Проще на сервере, но 250 КБ туда и обратно на каждую опечатку, а принять такую правку поверх нового черновика нельзя — она затрёт всё, что случилось после.
- **JSON Patch (RFC 6902).** Пути по индексам массивов (`/root/0/children/12/blocks/3`) ломаются от любой вставки выше и нечитаемы в очереди. Операции по id узла переживают перестановки.
- **Go SDK для MCP.** Лишняя зависимость ради четырёх методов (`initialize`, `ping`, `tools/list`, `tools/call`); транспорт без сессий и потоков пишется в сотню строк и тестируется тем же `httptest`.
- **OAuth вместо токена.** Правильно для публичного сервиса, избыточно для одного владельца и его агентов; токен с правами и отзывом закрывает задачу.

## Последствия

- Агент может видеть черновик, который ученикам не показан: это нужно, чтобы правки ложились на последнюю версию.
- Выводы программ сервер проверяет только на наличие. Запуск на сервере — открытый вопрос в плане; пока агент запускает код у себя и пишет об этом в описании правки.
- Новая операция над курсом — это `internal/course/changes.go`, описание в `agentRules` и в инструментах `mcp.go`.
