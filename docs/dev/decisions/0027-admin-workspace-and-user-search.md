# 0027. Рабочее пространство курса и поиск пользователей

Дата: 2026-11-17 · Статус: принято. Уточняет интерфейс [0025](0025-admin-preview-iframe.md) после просмотра владельцем.

## Контекст

Шапка и отдельная полоса режимов отнимали место у редактора. Панели вопросов и словаря перекрывали список. Выдача доступа требовала загрузить всех пользователей и отправить весь набор выбранных id, что неудобно при большом числе аккаунтов и может потерять параллельные изменения.

## Решение

Строка курса содержит вкладки и сохранение; вкладки прокручиваются внутри полосы, ниже 900 px переходят на отдельную строку. Внутри курса все страницы начинаются на расстоянии 24 px от левого края; глобальные списки остаются по центру. «Паспорт» в интерфейсе называется «Настройки», адрес `passport` сохранён для существующих ссылок. Удаление находится в настройках и требует ввода id; серверное правило `staffCourse` сохраняется.

Режимы редактора переключаются из шапок колонок. Режим «По ширине» по умолчанию использует всю колонку без масштаба; заданные ширины устройств уменьшаются только при нехватке места. Вопросы и термины редактируются рядом со списком. На телефоне та же форма открывается в полноэкранном нативном dialog; Esc и «К списку» возвращают фокус.

Общий компонент меню рассчитывает фиксированные координаты по кнопке: справа, снизу либо сверху, с ограничением границ окна. Прокрутка вне меню и изменение размера закрывают его. Компонент используется для аккаунта, действий и добавления узлов и блоков.

`GET /api/admin/users/search` доступен только админу: минимум два символа, предел выдачи 1–20, точный логин первым, затем логины по алфавиту. `owners=1` ограничивает кандидатов ролями admin/author. Ответ содержит id, логин, имя, роль, адрес аватара и отметку блокировки. Общий combobox задерживает поиск на 250 мс, игнорирует старые ответы и поддерживает стрелки, Enter и Esc.

Логин ищется через `users_login`; имя — через новое поле `name_search` и индекс `users_name_search`. Поле содержит `strings.ToLower(name)`, заполняется миграцией и обновляется при создании, регистрации по приглашению и смене имени. SQLite NOCASE сам не умеет приводить кириллицу. `%`, `_` и символ экранирования в запросе трактуются буквально.

Полный шаблон LIKE передаётся параметром (`префикс%`): SQLite не превращает выражение `? || '%'` в индексный диапазон. `COLLATE NOCASE` относится к столбцу, `ESCAPE` — к LIKE. Объединение двух индексных выборок убирает дубликаты. Go-тест проверяет `EXPLAIN QUERY PLAN` обеих ветвей.

`GET /api/admin/courses/{id}/users` ранее возвращал только id выданных доступов; теперь возвращает в `users` сведения только об этих людях, необходимые строкам с аватарами. Все потребители в репозитории обновлены. Для одной связи добавлены `POST` и `DELETE /api/admin/courses/{id}/users/{uid}` с политикой admin и журналом действий. Старый PUT всего набора сохранён; выдача курсов со стороны пользователя продолжает работать.

## Почему не иначе

Панель поверх списка не соответствует выбранному владельцем способу работы. Отдельный интерфейс превью расходился бы с ученическим движком; iframe и ограничения CSP из 0025 остаются. Поиск по всем загруженным аккаунтам не масштабируется. Один LIKE по исходному имени не покрывает русский регистр. Замена всего набора доступов ради одного человека может затереть независимое изменение.

## Последствия

Новая миграция добавляет только поле и индекс пользователей; формат курсов не меняется. Нормализованное имя требуется поддерживать во всех путях изменения имени. Старым внешним клиентам GET списка доступов нужно читать объекты вместо числовых id. Права нового API, сортировка, ограничения поиска, обновление нормализованного имени и использование индексов проверяются тестами. Геометрия меню, масштаб превью, подсказки и мобильная форма проверяются Node-тестами; окончательную визуальную проверку выполняет владелец.
