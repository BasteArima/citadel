# 0007. Вход по коду и синхронизация прогресса отметками

Дата: 2026-10-29 · Статус: принято

## Контекст

Этап 2: прогресс должен жить на сервере и не теряться между устройствами, а курс — работать и без сети. Пользователей единицы, полноценные аккаунты откладываются ([ARCHITECTURE](../ARCHITECTURE.md)).

## Решение

**Вход.** Имя и общий код доступа из `CITADEL_ACCESS_CODE`. Новое имя — новый пользователь, имя без учёта регистра. Роль админа — по списку `CITADEL_ADMINS`, сверяется при каждом входе.

- Сессия — случайный токен в cookie `HttpOnly`, `SameSite=Lax`, `Secure` за HTTPS. В базе только SHA-256 токена.
- Код сравнивается за постоянное время. После 10 неудачных попыток с адреса — пауза 10 минут.
- Запросы, меняющие данные, принимают только `application/json`: форма с чужого сайта так не отправит, а `SameSite=Lax` не пустит cookie.

**Прогресс** — набор отметок `{ ключ: { v, at } }`: `q:<урок>:<вопрос>`, `seen:<урок>:<часть>`, `done:<урок>`, `rev:<урок>:<повтор>`. `at` — время отметки по часам клиента.

- Клиент держит отметки в localStorage и отправляет серверу все свои. Сервер сливает по ключу — более свежая отметка побеждает — и возвращает итог. Отметки с других устройств приходят в том же ответе.
- Без сети отметки копятся и уходят при подключении, при возврате на вкладку и раз в минуту.
- Время из будущего сервер обрезает до «сейчас + минута»: убежавшие часы одного устройства не перебьют честные отметки навсегда.

**Курсы в базе.** При запуске курсы из `content/` сверяются по хешу с последней версией. Изменившийся курс становится новой опубликованной версией. Пока нет редактора, источник курсов — файлы.

## Почему не иначе

- **Прогресс одним документом «последний перезаписал всё».** Проще, но два устройства, поработавшие без сети, стирают отметки друг друга.
- **Часы сервера вместо часов клиента.** Отметка, сделанная без сети, получила бы время отправки, а не время ответа. На порядок отметок это почти не влияет, но смысл «когда решено» теряется. Обрезка будущего закрывает главный риск часов клиента.
- **Пароль у каждого пользователя.** Нужен, когда появятся люди кроме владельца и его знакомых — тогда полноценные аккаунты.
- **JWT вместо сессий в базе.** Сессию в базе можно отозвать удалением строки, JWT — нет.

## Последствия

- Отметки только добавляются: «снять отметку» сейчас нельзя. Понадобится — это будет отметка с другим значением, а не удаление.
- Открыть сайт совсем без сети пока нельзя: нужен service worker. Без сети работает уже открытая страница.
- Смена кода доступа не выкидывает уже вошедших. Если понадобится — удалить строки из `sessions`.
