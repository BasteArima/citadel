# 0009. Источник курса — база, `content/` — начальная загрузка

Дата: 2026-10-30 · Статус: принято

## Контекст

До этапа 5 курс жил в файле `content/<id>/course.json`: сервер при старте читал файлы и, если файл изменился, делал из него новую опубликованную версию. С редактором у курса появляется второй источник — правки в админке. Если оставить оба равноправными, перезапуск сервера с устаревшим файлом молча затрёт то, что админ поправил в редакторе.

Ещё одно: Go-курс пока пишется в формате v0 (`legacy/go-course/`) и собирается в v1 командой `task convert`. Сложные блоки (анимации, задания руками) удобнее писать файлом, чем формой, а API для агентов появится только на этапе 6.

## Решение

- **Источник правды — версии курса в базе.** Каждое сохранение в редакторе — новая версия; ученики видят только опубликованную ([0003](0003-agents-edit-via-drafts.md)).
- **`content/` — только начальная загрузка.** При старте сервер берёт файл, пока курс никто не правил в редакторе (автор последней версии — `content`). Как только появилась версия из админки, файл для этого курса пропускается, и в лог пишется, что он пропущен.
- **Черновик с ошибками сохраняется, но не публикуется.** Недописанная работа не теряется; сервер не даёт опубликовать версию, где `citadel check` находит ошибки.
- **Сохранение проверяет базовую версию.** Редактор присылает версию, от которой начал; если кто-то сохранил после неё — 409, а не тихая перезапись.
- **Откат — новая версия.** История не переписывается: «откатить к v3» кладёт копию v3 поверх.
- **Файл в базу — через «Импорт JSON».** Курс, собранный из v0 (`task convert`), или курс, написанный вне платформы, загружается в админке кнопкой «Импорт JSON» и становится новой версией черновика. Дальше — разница в «Версиях» и публикация.

## Почему не иначе

- **Файл главнее базы** (редактор пишет в `content/`): сервер в Docker пишет в свой том, а не в репозиторий, и правки из админки на домашнем сервере до git всё равно не дошли бы. Плюс два источника пришлось бы синхронизировать.
- **Всегда брать файл, если он новее**: «новее» по времени файла ненадёжно (git не хранит время), а по содержимому — это и есть тихая перезапись правок из редактора.
- **Запрет сохранять черновик с ошибками**: при правке курса с десятками уроков ошибка в одном блоке блокировала бы сохранение всей остальной работы.

## Последствия

- Резервная копия базы (`citadel backup`) теперь копия курсов, а не только прогресса. `content/` в git — снимок, по которому можно поднять курс с нуля, но не обязательно последняя версия.
- Чтобы снова вести курс файлом, нужен «Импорт JSON» (или, с этапа 6, API агента) — `task convert` сам по себе курс в базе не меняет, если его уже правили в редакторе.
- Поле `exam: false` у вопроса и поле `done` у узла правятся в редакторе; правило `done` движок пока не применяет (работает правило по умолчанию).
