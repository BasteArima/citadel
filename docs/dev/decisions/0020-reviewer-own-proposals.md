# 0020. Проверяющий принимает свои правки и новые курсы

Дата: 2026-11-10 · Статус: принято. Заменяет запрет собственной приёмки и приёмки новых курсов из [0019](0019-agent-reviewer.md).

## Контекст

Владелец поручил агенту подготовить творческие курсы, проверить их и принять через API. Право проверяющего уже выдано, но сервер запрещал приём своих предложений и любых новых курсов. Владелец явно попросил снять оба ограничения: ручной шаг в админке в этом процессе не нужен.

## Решение

- Токен с `CanReview` принимает свои и чужие предложения, включая новые курсы, через общую приёмку REST и MCP.
- Право действует только в пределах списка курсов токена. Создание предложения нового курса по-прежнему требует `CanCreate`; приёмка чужого предложения не требует этого права.
- Схема курса, состояние предложения, перебазирование, конфликты и проверка публикации сохраняются. Несовпавший вывод программы по-прежнему требует решения админа.
- Принятие создаёт неопубликованный черновик. Публикация остаётся отдельным действием проверяющего или админа.
- Право выдаёт и снимает админ. Новые права по умолчанию не появляются. В предложении и журнале остаётся имя принявшего токена; флаг `own` в очереди сохранён как информация об авторстве.
- Обновлены правила для агентов, описания MCP и тексты админки. Миграция данных и перевыпуск токенов не нужны.

## Почему не иначе

Отдельное право для собственной приёмки или ручная приёмка новых курсов оставили бы лишний шаг для личной установки. Владелец выбрал существующее право проверяющего как явную границу доверия.

## Последствия

Один агент может подготовить и принять весь курс без подмены токена. Независимая проверка остаётся рабочим процессом, а не серверным разделением авторства и приёмки. Ошибка проверки может попасть в публикацию, поэтому текст предложения и отчёт автора остаются данными, а решение принимается после проверки содержания. Изменение вступит в силу после деплоя обновлённого сервера.
