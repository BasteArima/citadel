# 0004. Гибкость курса без правки движка

Дата: 2026-10-29 · Статус: принято

## Контекст

Большинство курсов пойдут в общем формате: части, вопросы, анимации. Но курсу может понадобиться своя структура (разборы вместо уроков), свой раздел (шпаргалка, инструменты) или своё взаимодействие (тренажёр консоли). Это должно добавляться без переписывания движка и без поломки других курсов.

## Решение

1. Тип блока — модуль: схема, отрисовка, форма редактора, текст для озвучки, правило выполнения. Неизвестный тип — заглушка, а не ошибка.
2. Курс — дерево узлов любой глубины с настраиваемыми видами и подписями.
3. У курса есть свои страницы в меню. Справочник собран из таких же страниц.
4. Правило «пройдено» и интервалы повторений — настройки курса и узла.
5. Свой код курса — только в песочнице: iframe на отдельном адресе, общение сообщениями.
6. У формата есть версия, изменения сопровождаются миграциями.
7. Схемы блоков отдаёт API, чтобы агенты не гадали.

## Почему не иначе

- **Жёсткий формат «раздел → урок → часть».** Проще сейчас, но первый же нестандартный курс потребует правки движка.
- **Свой код курса прямо на странице.** Даёт полную свободу, но код из курса — а его может написать агент — получает доступ к прогрессу, токенам и админке.

## Последствия

- Движок сложнее, чем сейчас: реестр модулей и общий интерфейс блока.
- Песочницу откладываем, пока она не понадобится первому курсу, но формат сразу оставляет для неё место (блок `embed`).
