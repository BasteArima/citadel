# 0021. HTML курса — по белому списку, страницы — под CSP

Дата: 2026-11-12 · Статус: принято

## Контекст

Текст блоков курса — «простой HTML» ([CONTENT-FORMAT](../CONTENT-FORMAT.md)). Движок вставляет его в страницу через `innerHTML` (`rich()` в `web/static/engine/rich.js`) и ничего не фильтрует. Пока курсы пишет только владелец, это не страшно. Но скоро курсы станут писать другие люди и их агенты ([0023](0023-course-authors.md)). Тогда строка вида `<img src=x onerror="…">` в курсе выполнит скрипт на основном адресе сайта у любого, кто откроет курс или его черновик. Cookie сессии `HttpOnly`, и украсть её скрипт не может. Но он может вызвать API от имени того, кто смотрит. Если смотрит админ, скрипт выпустит токен, поменяет роли или опубликует курс.

Тот же путь открыт для внедрённой инструкции: агент, которого обманули, может вписать такой HTML в правку.

Что реально используется в курсах владельца (12.11.2026): `code`, `div class`, `b`, `small`, `pre`, `i`, `br`, `a href="#…"`. Атрибут `style`, картинки и внешние ссылки не встречаются. Нашлась и ошибка в контенте: в Go-курсе 6 раз встречается «`<nil>`» прямо в тексте. Браузер считает его неизвестным тегом и ничего не показывает.

## Решение

Защита в три слоя. Каждый закрывает то, что пропустил предыдущий.

**1. Проверка курса (сервер).** `course.Validate` проверяет каждое HTML-поле (`p`, `html`, `title`, `cap`, тексты вопросов и ответов, словарь, паспорт — всё, что попадает в `rich()`). Разрешено только:

| Тег | Атрибуты |
|---|---|
| `b`, `strong`, `i`, `em`, `u`, `s`, `small`, `sub`, `sup`, `mark`, `code`, `kbd`, `pre`, `br`, `p`, `span`, `div`, `ul`, `ol`, `li`, `blockquote`, `table`, `thead`, `tbody`, `tr`, `th`, `td` | `class` |
| `a` | `class`, `href`: только `#…`, относительный `/…` или `https://…`. Внешней ссылке движок сам добавляет `target="_blank" rel="noopener noreferrer"` |

Всё остальное — ошибка проверки с понятным текстом: «тег `<nil>` не разрешён — если это текст, напиши `&lt;nil&gt;`», «атрибут `onerror` не разрешён». Курс с такой ошибкой не публикуется, а правку агента с ней нельзя принять. Это уже так для любых ошибок проверки ([0010](0010-agent-api-and-mcp.md)). Разбирает HTML настоящий парсер (`golang.org/x/net/html`), а не регулярное выражение.

**2. Фильтр при выводе (браузер).** Черновики, старые версии и правки агентов в очереди могут содержать ошибки, а админ их открывает. Поэтому `rich()` пропускает результат через фильтр с тем же белым списком. Фильтр разбирает строку в `<template>` (там скрипты не выполняются, а картинки не грузятся), обходит дерево, переносит разрешённое и превращает запрещённые теги в текст. К белому списку добавлены разметка самого движка: `button.term[data-k]` для терминов и `a.xref[href^="#"]` для ссылок на узлы. Фильтр — свой модуль `web/static/engine/sanitize.js` без зависимостей.

Ещё одно правило для этого слоя: всё, что приходит из курса, попадает в `innerHTML` только через `rich()` (HTML-поля) или `esc()` (простой текст: заголовки, имена, команды). Каждое место вставки проверено по этому правилу.

**3. CSP (сервер).** Каждая HTML-страница отдаётся с заголовком:

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data:; media-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'
```

Встроенные `<script>` из `web/*.html` (ранняя установка темы, скрипт страницы входа) переезжают в файлы `/static/…`. Тема ставится тем же блокирующим скриптом в `<head>`, поэтому мигания нет. `style-src 'unsafe-inline'` остаётся, потому что движок задаёт стили в разметке анимаций. Атрибут `style` из курса и так отсекают слои 1 и 2.

**Существующие курсы.** Перед выкладкой владелец исправляет свои курсы: прогоняет `citadel check` и заменяет `<nil>` на `&lt;nil&gt;`. Для тестового курса это делает тот, кто реализует решение. Правило «каждый вывод получен запуском» при этом не нарушается: меняется только запись символов, а не сам вывод.

**Будущий собственный код курса** (интерактивные компоненты) — по-прежнему только в изолированном iframe на отдельном адресе ([AGENTS.md](../../../AGENTS.md)). Белый список для него не расширяется.

## Почему не иначе

- **Только CSP.** Без `unsafe-inline` для скриптов обработчики `onerror` не выполнятся. Но CSP не спасёт от поддельной кнопки «Войти» со ссылкой на чужой сайт и от разметки, которая перекрывает интерфейс. Кроме того, это одна линия защиты, а любая ошибка в заголовке открывает дыру целиком.
- **Только фильтр в браузере.** Плохой HTML тогда тихо лежал бы в курсе, а автор не узнал бы, почему его разметка пропала. Проверка на сервере даёт понятную ошибку там, где курс пишут.
- **Тихо чистить HTML при сохранении.** Контент меняется без ведома автора. Так `<nil>` из Go-курса просто пропал бы со страницы.
- **DOMPurify.** Надёжная библиотека, но это первая внешняя зависимость фронтенда ради сотни строк. Наш белый список маленький, а обход DOM через `<template>` проверяется тестами.
- **Markdown вместо HTML.** Правильно для нового формата, но это миграция всех курсов и редактора. Решение с белым списком совместимо с тем, что уже есть.

## Последствия

- Курс с запрещённым HTML не публикуется. Агенты получают это как ошибку `check_changes` и исправляют сами.
- Разрешить новый тег — значит поменять список в двух местах: Go (`internal/course`) и JS (`sanitize.js`). Тест сверяет, что списки совпадают.
- Картинки из внешних источников в курсе запрещены (`img-src 'self' data:`). Понадобятся — отдельное решение о загрузке картинок на сервер.
- Это обязательный шаг перед тем, как пускать авторов ([0023](0023-course-authors.md)).
