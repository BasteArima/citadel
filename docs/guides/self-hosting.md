# Как поднять Citadel у себя

Citadel — одна программа в Docker-контейнере. Данные (курсы с версиями, пользователи, прогресс) лежат в одном файле SQLite в Docker-томе. Рядом работают исполнитель кода курсов и прокси к Docker — см. «Запуск кода курсов».

## Что нужно

- Docker с Compose (Docker Desktop на Windows и macOS или Docker Engine на Linux).
- Для удобства — [Task](https://taskfile.dev): `go install github.com/go-task/task/v3/cmd/task@latest`. Без него все команды ниже есть и в «сыром» виде.

## Первый запуск

1. Склонируй репозиторий и перейди в папку.
2. Скопируй `.env.example` в `.env` и задай `CITADEL_RUNNER_SECRET` — секрет между Citadel и исполнителем кода, не короче 24 символов. Сгенерировать: `openssl rand -base64 32`.
3. Подними: `task up` или `docker compose up -d --build`.
4. Создай первого админа (вместо `citadel` подставь имя контейнера):
   ```sh
   docker exec -it citadel citadel user add --role admin --name "Владелец" baste
   ```
   Команда один раз напечатает случайный пароль. Он не попадает в лог сервера. Храни его у себя, не пересылай вывод консоли.
5. Открой `http://localhost:8080`, введи логин `baste` и полученный пароль. В профиле смени пароль на свой.

Логин — 3–32 символа: латиница, цифры, точка, дефис, подчёркивание; первый символ — буква или цифра. Регистр не важен. Имя — отдельное отображаемое поле (1–40 букв, цифр, пробелов, `.-_`), его можно поменять в профиле. Логин и имя уникальны. Пароль — от 10 до 256 символов и не совпадает с логином. Новые аккаунты пока создают через `citadel user add --name "Имя" <логин>`; приглашения появятся следующим шагом.

## Домен через Nginx Proxy Manager

1. В Nginx Proxy Manager: **Hosts → Proxy Hosts → Add Proxy Host**.
2. Domain Names — твой домен, Scheme — `http`, Forward Hostname — адрес машины с контейнером, Forward Port — `8080`.
3. На вкладке SSL выпусти сертификат Let's Encrypt, включи **Force SSL** и **HTTP/2**.

Nginx Proxy Manager передаёт заголовок `X-Forwarded-Proto: https`. По нему Citadel ставит сессионной cookie флаг `Secure`, и она ходит только по HTTPS.

Если NPM и Citadel на одной машине в Docker, можно не открывать порт наружу: убери `ports` из `compose.yaml`, подключи контейнер к сети NPM и укажи в Forward Hostname имя контейнера `citadel`.

## Portainer и готовый образ

Образ собирает GitHub Actions и публикует в `ghcr.io/bastearima/citadel`. В нём только код и тестовый курс.

1. В Portainer: **Stacks → Add stack**, вставь в редактор `deploy/portainer-stack.yml`.
2. В разделе переменных задай `CITADEL_PORT` и `CITADEL_RUNNER_SECRET` вручную или файлом через **Load variables from .env file**.
3. Нажми **Deploy the stack**. Контейнер `go-toolchain` скачает образ Go и завершится, это нормально.
4. В **Containers → контейнер Citadel → Console** выбери `/bin/sh` и выполни `citadel user add --role admin --name "Владелец" baste`. Войди с напечатанным паролем и смени его в профиле.
5. Свои курсы загрузи в админке: **Курсы → Импорт JSON**, затем опубликуй. Тестовый курс стек не загружает: сервис стартует пустым.

Обновить: **Stacks → citadel → Update the stack** с включённым **Re-pull image**. Том с базой останется на месте.

## Свои курсы

Папка `content/` не попадает в git и в образ. Команда `task run` загружает курсы из неё, а если её нет — тестовый курс из `content-demo/`. Чтобы `task up` тоже брал свои курсы, добавь в `.env` строку `CITADEL_CONTENT_DIR=./content`.

## Обновление

```
git pull
task up
```

При запуске сервер сверяет курсы из `content/` с базой. Изменившийся курс становится новой опубликованной версией, прежние остаются в истории. Прогресс учеников не трогается: он хранится по id вопросов, а id не меняются.

Это касается только курсов, которые ещё не правили в админке. Как только у курса появилась версия из редактора, файл из `content/` для него пропускается (в логе — `course file skipped`): иначе обновление сервиса затёрло бы правки. Новую версию из файла такого курса загружают в админке кнопкой «Импорт JSON» — она станет черновиком, и её публикуют после просмотра разницы.

## Админка

Админка — `/admin`, ссылка «Админка» видна в шапке у админов. Курс бывает публичным (его видят все вошедшие) или приватным (видят админы и те, кому ты выдал его в «Пользователях»); переключатель — в таблице «Курсы». Роль хранится в базе и меняется в «Пользователях» или командой `citadel user set-role <логин> admin`. Там же можно заблокировать и разблокировать аккаунт: блокировка сразу закрывает его сессии, прогресс сохраняется. Себя через админку и последнего активного админа заблокировать или понизить нельзя.

## Запуск кода курсов

Кнопка «Запустить на сервере» в редакторе, инструмент агента `run_code` и проверка выводов в правках агентов запускают код курса на сервере (решение `docs/dev/decisions/0013-running-course-code.md`). Каждый запуск — одноразовый контейнер без сети, без томов, под непривилегированным пользователем, с лимитами на память, процессы, процессор, диск, вывод и время. Запускать могут только админы и агенты, ученики — нет.

`task up` поднимает для этого три сервиса из `compose.yaml`:

- `runner` — исполнитель: получает от Citadel код и создаёт контейнер под запуск;
- `docker-proxy` — прокси к сокету Docker: пропускает только операции с контейнерами, всё остальное закрыто;
- `go-toolchain` — только скачивает образ `golang:1.27-alpine` и сразу выходит. Это нормально: сам исполнитель скачивать образы не может.

Без `CITADEL_RUNNER_SECRET` исполнитель не стартует, а Citadel работает как раньше — просто без кнопок запуска.

### gVisor на домашнем сервере (рекомендуется)

Контейнеры делят ядро с хостом, и уязвимость ядра теоретически может вывести код из контейнера. [gVisor](https://gvisor.dev) запускает контейнер со своим ядром в пространстве пользователя и закрывает этот путь. На Linux (Debian, Ubuntu) — по [официальной инструкции](https://gvisor.dev/docs/user_guide/install/):

```
curl -fsSL https://gvisor.dev/archive.key | sudo gpg --dearmor -o /usr/share/keyrings/gvisor-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/gvisor-archive-keyring.gpg] https://storage.googleapis.com/gvisor/releases release main" | sudo tee /etc/apt/sources.list.d/gvisor.list
sudo apt-get update && sudo apt-get install -y runsc
sudo runsc install
sudo systemctl reload docker
docker run --rm --runtime=runsc hello-world
```

Если последняя команда напечатала приветствие, впиши в `.env` строку `CITADEL_RUNNER_RUNTIME=runsc` и выполни `task up`. В логе исполнителя (`docker compose logs runner`) будет `"runtime":"runsc"`. На Docker Desktop под Windows gVisor недоступен — там Docker и так работает внутри виртуальной машины.

## Озвучка курсов

Записи озвучки делает сам Citadel: раздел «Озвучка» курса в админке → «Озвучить изменённое» (как устроено — `docs/dev/AUDIO.md`). Синтез — программа `edge-tts`, она уже есть в образе. Файлы лежат в том же томе, что и база (`/app/data/audio`), и попадают в бэкап тома, но не в бэкап базы (`task backup`): после восстановления из бэкапа базы записи можно сделать заново той же кнопкой.

Серверу нужен выход в интернет к `speech.platform.bing.com`. Проверка из контейнера:

```
docker exec citadel sh -c 'echo "Проверка" > /tmp/t.txt && edge-tts --voice ru-RU-SvetlanaNeural --file /tmp/t.txt --write-media /tmp/t.mp3 && ls -l /tmp/t.mp3'
```

Если команда висит дольше минуты, а файла нет — хост недоступен напрямую. Тогда впиши в `.env` HTTP-прокси, `CITADEL_TTS_PROXY=http://адрес:порт`, и выполни `task up`. В логе Citadel при старте — строка `"msg":"narration"` с `"proxy":true`.

## Подключить агента

Вкладки с настройками есть для Claude Code, Codex (CLI и приложение), Cursor, Antigravity, Gemini CLI и других MCP-клиентов. В админке, «Пользователи и токены» → «+ Новый токен»: название, права (читать, предлагать правки, создавать курсы) и курсы. После создания админка один раз покажет токен и готовую команду для Claude Code:

```
claude mcp add --scope user --transport http citadel https://<твой домен>/mcp --header "Authorization: Bearer cit_…"
```

Команда выполняется на ПК, где работает Claude Code. Агент получает инструменты Citadel: читать курсы и схему блоков, запускать код (`run_code`), проверять и отправлять правки, узнавать их статус. Публиковать он не может: правки приходят в «Правки агентов», принимаешь их в черновик и публикуешь ты. Токен в базе не хранится (только его хеш) — потерял, отзови и выпусти новый. Через Nginx Proxy Manager `/mcp` проходит как обычный адрес сайта, отдельных настроек не нужно.

## Бэкап

```
task backup
```

Копия базы появится в `backups/citadel-<дата>.db`. Её можно делать на ходу: копию пишет сам SQLite (`VACUUM INTO`), поэтому запись, которая идёт в этот момент, не испортит копию. Простое копирование файла базы во время работы так не умеет.

Без Task:

```
docker compose exec citadel citadel backup -out /app/data/backup.db
docker compose cp citadel:/app/data/backup.db backups/backup.db
docker compose exec citadel rm /app/data/backup.db
```

Храни бэкапы не только на той же машине.

## Восстановление из бэкапа

```
docker compose down
docker run --rm -v citadel_citadel-data:/data -v "$PWD/backups:/b:ro" alpine sh -c "rm -f /data/citadel.db-wal /data/citadel.db-shm && cp /b/<файл>.db /data/citadel.db && chown 10001 /data/citadel.db"
docker compose up -d
```

`citadel_citadel-data` — имя тома: папка проекта плюс `citadel-data`. Если папка называется иначе, посмотри имя в `docker volume ls`. `chown 10001` нужен потому, что программа в контейнере работает не от root.

## Если забыл пароль

Сервер останавливать не нужно. В консоли Portainer (**Containers → Citadel → Console → /bin/sh**) выполни:

```sh
citadel user list
citadel user reset-password baste
```

Или с хоста: `docker exec -it <контейнер> citadel user reset-password baste`. Команда один раз печатает новый случайный пароль из 20 букв и цифр и закрывает все сессии аккаунта. Войди и смени пароль в профиле. Если аккаунт заблокирован, сначала `citadel user unblock baste`. Если админа больше нет — `citadel user add --role admin --name "Владелец" baste` с новым уникальным логином и именем.

Другие команды: `citadel user set-role baste admin`, `citadel user set-role <логин> author`, `citadel user unblock <логин>`. До появления прав автора роль `author` даёт возможности ученика. По умолчанию команды используют `CITADEL_DATA` (в образе `/app/data`); другую базу указывают флагом `-data <каталог>`, например `citadel user list -data /app/data`.

## Переход со входа по коду

1. Сделай бэкап базы (раздел «Бэкап»).
2. Удали `CITADEL_ACCESS_CODE` и `CITADEL_ADMINS` из переменных стека Portainer и из `.env`. Они больше не дают доступ и не назначают админов. Если остались, при старте будет одно предупреждение без значений.
3. Обнови стек из `deploy/portainer-stack.yml`: **Stacks → citadel → Editor → Update the stack → Re-pull image**. Том с базой сохрани. Не удаляй стек вместе с томами.
4. В консоли контейнера Citadel выполни:
   ```sh
   citadel user list
   citadel user reset-password baste
   ```
   Логин автоматически проставится из старого имени, если оно подходит под правила после перевода в нижний регистр. При совпадении логин получает аккаунт с меньшим id, остальным нужно назначить другой. Если у твоего аккаунта логин пуст (например, имя кириллицей), используй id из списка:
   ```sh
   citadel user reset-password --id 1 --login baste
   ```
   Подставь свой id и свободный логин. Команда сохраняет пользователя, роль, доступы и прогресс, задаёт пароль и закрывает его старые сессии. Заблокированного админа сначала разблокируй командой `citadel user unblock baste`.
5. Войди с полученным паролем и смени его в профиле. Для остальных старых пользователей повтори сброс отдельно. Пока пароль не задан, нового входа в их аккаунт нет; действующие сессии сохраняются до истечения или сброса пароля.

Если при старте нет незаблокированного админа с логином и паролем, лог подсказывает `citadel user reset-password <login>` или `citadel user add --role admin …`. Роли существующих аккаунтов сохраняются в базе; настройка больше не повышает их роль при входе.

В профиле смена пароля требует текущий пароль и сохраняет только текущее устройство. «Выйти на всех устройствах» закрывает все сессии, включая текущую.

## Логи и проверка

```
task logs
```

Логи исполнителя кода — `docker compose logs runner`: по строке на запуск, с кодом выхода и временем, без самого кода. `GET /healthz` отвечает `ok`, когда сервер работает. По нему же Docker помечает контейнер как healthy. Ограничения неудачных входов: 10 за 10 минут по IP и 10 за 15 минут по логину. На любую ошибку входа — один текст «Логин или пароль не подошли».
